# Module: Tasks

Entity `Task`, `services/task_io.py` and the *Tasks* page (`/tasks`). A task is one test: prompt, attachments, required capabilities, expected artifacts, rubric for the judge, reference answer and automatic `checks`. The user can add as many tasks as desired; the app ships a **seed battery** of very hard, verifiable tasks.

## Task anatomy

- **Prompt**: the instruction shown to the evaluated model. Answer tasks must ask for a last line `FINAL ANSWER: <value>`; for file tasks the runner appends the delivery format automatically when `artifact_names` is set ([artifacts-sandbox.md](artifacts-sandbox.md), [../05-llm/prompts.md](../05-llm/prompts.md)).
- **Attachments**: images (`image/*`) are sent as image parts only to profiles with `vision`; text documents (`text/*`, `application/json`, or `inline_text=true`) are embedded before the prompt as `<document name="…">…</document>` and are also readable by agents through `read_attachment`. Seed attachments reference files in `src/aidriven/seed/assets/` by `path`; uploaded ones are stored as `data_b64`.
- **requires**: `vision`, `tools`, `json_mode` — an item whose model lacks one becomes `skipped` at run creation (not a failure).
- **expected_artifact** + **artifact_names**: what files the task asks for (`["lisp.py"]`).
- **rubric** and **reference_answer**: judge-only; never sent to the evaluated model.
- **checks**: see the kinds below. Each has `dimension` (`intelligence` | `conformity`), `weight`, `timeout_s` (default 60).
- **difficulty**: `medium` | `hard` | `extreme` (informative; the dimensions do not weight by difficulty).

## Check kinds

| `kind` | Runs | Uses | Credit |
|---|---|---|---|
| `exact` | in-process | `expected`, `pattern` (answer extractor; default last `FINAL ANSWER`), `case_sensitive` | 0/1, whitespace/trailing-dot normalized |
| `regex` | in-process | `pattern`, `target` (artifact name, or the response) | 0/1 |
| `numeric` | in-process | `expected`, `tolerance` (absolute), `pattern` | 0/1 |
| `json_schema` | in-process | `schema`, `target` (else last ```` ```json ```` block, else the response) | 0/1 (errors in `detail`) |
| `python_tests` | sandbox | `code` (hidden tests with the harness), `files`, artifacts | weighted passed/total |
| `python_verifier` | sandbox | `code` reading `response.txt` / artifacts, printing `AIDRIVEN_RESULT` via the harness | partial 0..1 |
| `html_playwright` | sandbox (Playwright image) | `code` with `open_page(...)` | passed/total; skipped if Playwright is unavailable |
| `sql_result` | sandbox | `files["setup.sql"]`, artifact `target` (default `query.sql`), `expected` rows | 0/1, ordered row equality |

Details and the sandbox contract are in [evaluation.md](evaluation.md). Hidden test code and `files` are never sent to the evaluated model (they only reach the sandbox and the task editor/exports).

## Seed battery (`src/aidriven/seed/tasks/*.yaml`)

Tasks designed to be hard for current frontier models, objectively verifiable and **free of guardrail triggers** (purely technical and logical). Each YAML file is one task (`slug`, `title`, `category`, `difficulty`, `prompt`, `artifact_names`, `rubric`, `reference_answer`, `checks`, optional `attachments`); the loader sets `id = seed_<slug>`, `source = "seed"` and, for checks without an explicit `id`, the deterministic check id `<slug>#<index>` (stable across seed versions, so per-check comparisons keep working). Assets are regenerated byte for byte by `tools/gen_seed_assets.py` (a 9×7 shapes grid PNG for a vision task and three long-context "Norrbeck" documents: staff directory, H1 expense ledger, finance policy). Reference solutions live in `tests/fixtures/seed_solutions/<slug>/` (served by the fake `oracle`).

The battery is complete with **14 tasks** (`01-lisp-interpreter.yaml` … `14-shape-grid-vision.yaml`):

## Task editor and page

- Table (sorted by category, slug) with search (slug, title, tags), category and source filters; columns slug, title, category, difficulty, #checks, requires, source, version, enabled; row selection; actions *Quick run*, *Edit*, *Enable/disable*, *Delete*.
- Editor tabs: *General* (slug, title, category, difficulty, requires, expected artifact, artifact names, tags, enabled) · *Prompt* · *Checks* (YAML list in a code editor, with a template; **Try checks** runs them against a pasted sample answer, showing the extracted files and each check's score and detail) · *Judge* (rubric, reference answer) · *Attachments* (upload, ≤ 512 KiB each; `.txt/.md/.csv/.json` and `text/*` become inline text documents).
- Saving requires slug, title and prompt; the slug must be unique; editing increments `version`.
- **Quick run** (row action or *Run selected*): choose profiles, repetitions and the judge switch → creates and starts a run without a suite and opens it.
- **Import** (paste or upload YAML/JSON, one task or a list) and **Export** YAML/JSON (selected tasks, or all).

## Business rules

- **Seed sync** at every start (`sync_seed_tasks`): a seed task is inserted when missing or replaced when the YAML `version` is higher than the stored one (keeping `created_at` and `enabled`). User edits of a seed task bump its version, so they survive until a newer seed version ships. A deleted seed task is restored on the next start (the delete dialog says so and suggests disabling instead).
- **Import** (`import_tasks`) upserts by `slug`: an existing slug keeps its id and `created_at`, gets `version + 1` and keeps its source (`seed` becomes `import`); new slugs are created with source `import`. There are no skip/copy options.
- **Export** writes the full task (including checks' code, `files`, rubric and reference answer, by alias `schema`) without `created_at`/`updated_at`; seed attachments are exported by `path`, uploaded ones as base64. There is no "public" export mode yet.
- Disabled tasks remain selectable in suites (marked "(off)") and runnable.
- Every edit increments `version`; only the latest version is stored; runs keep their snapshot ([ADR-017](../01-architecture/adr/ADR-017-run-snapshot-and-rerun-as-built.md)).

## Acceptance criteria

- [x] Every seed task has checks and a rubric, and slugs are unique (`test_infra.py::test_seed_tasks_are_valid`).
- [x] Every seed task's reference solution scores 1.0 on every non-skipped check, and a non-answer (`"I don't know.\nFINAL ANSWER: 0"`, no files) does not pass all checks and is not fully skipped (`test_seed_reference.py`).
- [x] Exporting a task to YAML and importing it creates it; importing again creates version 2 (`test_infra.py::test_task_export_import_roundtrip`).
- [x] A vision task on a profile without vision produces a `skipped` result, not an error (`test_runner.py::test_skip_when_capability_missing`).
- [ ] CRUD of tasks from the UI, including checks of every kind and image attachments.
- [ ] Editing a task increments `version`; a previous run still shows the old prompt from its snapshot.
- [ ] Hidden test code never appears in the request sent to the evaluated model.
